# PokéBonk 학습봇

[PokéBonk](https://pokebonk.com/?lang=ko)를 직접 플레이하면서 **스테이지 클리어와 고득점**을 목표로 전략을 스스로 개선하는 봇입니다.
자동 조작은 수단일 뿐이고, 봇이 판단하는 기준은 처음부터 끝까지 "이 행동이 최종 점수를 올리는가"입니다.

## 게임 분석 (클라이언트 코드에서 확인한 규칙)

### 점수 공식 (일반 모드)

```
점수 = (처치×2 + 생존초×3 + 준 피해/200 + (도달 스테이지-1)×1500 + 보스 처치×800 + 승리 6000) × (1 + 난이도×0.5)
```

- **스테이지 진행과 보스 처치가 점수의 핵심**입니다. 승리(전설 보스 처치) 하나가 6000점이고, 다음 스테이지로 넘어갈 때마다 1500점, 보스 하나당 800점입니다.
- 생존 시간(초당 3점)과 처치 수(2점)도 쌓이므로, 각 스테이지에서 **버틸 수 있는 만큼 성장하고 나서** 보스를 부르는 게 유리합니다.

### 스테이지 흐름

1. 스테이지 맵에 **보스 제단**(`boss`, "수호자를 깨운다")이 하나 있습니다. 상호작용(E)하면 그 스테이지의 수호자가 나옵니다.
2. 수호자를 쓰러뜨리면 **포털**과 **보상 슈퍼볼**(무료 아이템)이 생깁니다. 포털로 다음 스테이지로 넘어갑니다.
3. 3스테이지에서는 **전설의 포켓몬**이 나오고, 쓰러뜨린 뒤 포털에 들어가면 맵 클리어(승리)입니다. 성역이 있는 지역은 4스테이지가 추가됩니다.
4. 스테이지 시간 **600초(10분)부터 "최종 대군"**이 시작되고, 적 체력이 분당 4배씩 늘어납니다. 그 전에 보스를 잡아야 합니다.

### 맵 오브젝트

| 오브젝트 | 효과 |
|---|---|
| 충전 제단(`altar`, 등급 0~3) | 원 안에 서 있으면 충전되고, 다 차면 **축복**(영구 스탯 강화) 선택. 높은 등급은 충전 중 적 웨이브가 오고, 3등급은 90초 전엔 봉인 |
| 슈퍼볼(`freechest`) | 무료 아이템 |
| 포켓볼(`chest`) | 골드로 여는 아이템 상자(열수록 비싸짐) |
| 도전 제단(`challenge`) | 적 웨이브를 이기면 슈퍼볼 |
| 저주 제단 / 저주받은 볼 | 희귀 아이템 대신 적 +15%, 난이도 +10% / 난이도 +5%와 매복 |
| 팬텀 제단(`greed`) | 난이도 +20% 대신 경험치·전리품 +25% |
| 나옹 상점, 메타몽(아이템 복제), 잠만보(축복/골드), 자석(경험치 흡수), 열매(체력 50% 회복), 바위(골드), 우리(골드로 경험치) | 상황에 따라 유용 |

### 성장

- 레벨업마다 3지선다: 새 기술 / 기술 강화 / 비타민(스탯). 희귀도가 높을수록 효과가 큽니다.
- 공격은 자동입니다. 플레이어가 하는 일은 **이동, 상호작용(E), 점프·슬라이드, 궁극기(R), 선택지 고르기**뿐입니다.
- 가만히 서 있으면 1레벨 캐릭터는 20초 안에 죽습니다. 회피 이동이 필수입니다.

## 봇 구조

```
src/harness.js   Playwright로 실제 게임 클라이언트를 띄우고, 봇이 게임 객체를 읽을 수 있게 연결
src/agent.js     게임 페이지 안에서 도는 전략 에이전트 (판단 + 조작)
src/policy.js    학습되는 정책: 전략 파라미터 + 선택 선호도
src/train.js     학습 루프
src/play.js      학습된 정책으로 플레이 (관전 모드 포함)
policy/policy.json  지금까지 학습된 정책
src/report.js    학습 진행 요약
runs/*.jsonl     매 판 기록 (점수, 스테이지, 선택 내역 등, 로컬 전용)
```

### 조작 방식

봇은 사람이 쓰는 것과 같은 입력만 씁니다: 가상 아날로그 스틱(이동), E(상호작용·몬스터볼), Space(점프), Shift(슬라이드), R(궁극기), 그리고 레벨업·축복·아이템 선택창에서 하나 고르기.
상태(내 위치·체력, 적, 탄환, 아이템, 제단, 보스)는 게임 객체에서 직접 읽습니다.

### 전략 (스테이지마다 반복)

1. **성장(farm)**: 각 맵 오브젝트의 가치를 `가치 / (1 + 거리/거리척도)`로 평가해 가장 이득인 곳으로 이동합니다. 충전 제단은 원 안에 머물러 충전하고, 상자는 골드가 있을 때만 엽니다. 초반(낮은 레벨)에는 가까운 곳만 노리고 경험치 수집을 우선합니다. 보스 호출 시각까지 남은 시간 안에 보스 제단으로 돌아올 수 없는 목표는 고르지 않습니다.
2. **보스 호출**: 스테이지 시간이 그 스테이지의 보스 호출 시각(학습됨)에 도달하면 보스 제단으로 가서 보스를 깨웁니다.
3. **보스전**: 보스 주위를 선호 거리(학습됨)로 공전하면서 탄환과 돌진을 피하고, 궁극기를 씁니다.
4. **정리 후 이동**: 보스가 떨군 슈퍼볼을 모두 연 뒤 포털로 다음 스테이지로 갑니다.
5. **마지막 스테이지 마무리**: 마지막 보스(전설)를 쓰러뜨리면 포털 옆을 돌면서 계속 싸웁니다. 생존 시간·처치·피해가 계속 점수가 되고, 시간이 갈수록 강해지는 대군을 상대로 피해 점수가 크게 쌓입니다. 정해진 시간이 지나거나 체력이 기준 아래로 떨어지면 바로 포털에 들어가 승리(+6000)를 확정합니다. 머무는 시간과 탈출 체력 기준은 학습됩니다.

이동은 매 0.1초(게임 시간)마다 16방향을 평가해서 고릅니다. 평가 항목은 목표 방향, 경험치 덩어리, 회복 아이템, 적과의 거리(1.2·3·6칸 앞을 미리 봄), 적 무리 쪽으로 들어가는지, 적 탄환의 예상 경로, 맵 경계·지형지물·깊은 물입니다.
1초 동안 제자리면 점프하면서 적이 적은 쪽으로 빠져나옵니다. 체력이 낮고 포위되면 슬라이드로 탈출합니다. 도달하지 못하는 목표는 일정 시간 뒤 포기하지만, 충전 제단 안에 있는 동안은 포기 타이머가 멈춥니다.

**보스 공격 회피**: 보스의 범위 공격은 모두 예고 표시(원·직선)를 먼저 그리고, 약 0.75~1.2초 뒤 시전할 때의 위치를 때립니다. 봇은 게임이 예고 표시를 그리는 순간(`vfx.telegraph`, `vfx.beams`)과 보스의 공격 함수 호출을 감지해서 위험 지역과 판정 시각을 기록합니다. 이동 방향을 고를 때는 **위험 지역에 들어가지 않는 방향을 먼저 거른 뒤** 나머지 점수로 고릅니다. 바닥을 따라 퍼지는 충격파는 점프로만 피할 수 있어서, 링이 도달하기 직전에 점프합니다.

초반(레벨이 낮을 때)에는 별도 파라미터로 더 조심스럽게 움직이고 경험치를 우선합니다.

### 학습

- **전략 파라미터 약 60개**(스테이지별 보스 호출 시각, 위험 회피 강도, 보스전 거리, 오브젝트별 가치, 고등급 제단을 시도할 레벨 등)는 **진화 전략(antithetic ES)**으로 학습합니다. 같은 노이즈를 +/−로 뒤집은 두 정책을 **같은 맵 시드**에서 실제로 플레이시켜 비교하고, 점수가 더 높은 쪽으로 평균을 옮깁니다. 점수가 수백~수십만 점까지 벌어지기 때문에 비교는 로그 점수로 합니다.
- **선택 선호도**(레벨업에서 어떤 기술·비타민을, 축복에서 어떤 스탯을, 상자에서 어떤 아이템을 고를지)는 판 결과로 갱신합니다. 기준 점수보다 잘 나온 판에서 고른 선택지는 선호도가 올라가고, 못 나온 판에서 고른 선택지는 내려갑니다.
- 한 번도 골라 보지 않은 선택지는 0점이 아니라 평균 선호도로 평가해서, 초반에 우연히 고른 것만 계속 고르는 편향을 막습니다.
- 매 세대가 끝날 때마다 `policy/policy.json`에 저장하므로, 언제 멈추고 다시 시작해도 이어서 학습합니다.

### 서버와 랭킹에 대해

학습은 수백 판을 반복하므로 **실제 서버(`api.pokebonk.com`)에는 아무것도 보내지 않습니다**. 하네스가 게임의 API 요청을 로컬에서 대신 응답합니다. 그래서 봇이 낸 점수는 공식 랭킹에 올라가지 않고, 다른 플레이어에게 영향을 주지 않습니다.
게임 코드 자체(전투, 적, 드롭, 맵 생성)는 `pokebonk.com`에서 받은 실제 클라이언트 그대로 돌아갑니다.

## 현재 성능

숲(forest) 지역, 파이리, 난이도 0 기준. 이 저장소의 `policy/policy.json`(22세대, 227판 학습)으로 평가했습니다.

| | 승리(맵 클리어) | 점수 |
|---|---|---|
| 학습 전 기본 정책 (첫 실험 판들) | 0% (모두 1스테이지 보스전에서 사망) | 약 600~5,000 |
| 학습 1~2세대 | 약 10~30% | 중앙값 약 1만 |
| 학습 후 최근 72판 (탐색 노이즈 포함) | 78% | 중앙값 309,511 |
| **학습 후 평가 10판 (노이즈 없음)** | **90% (9/10)** | **331,499 ~ 557,555, 중앙값 약 387,000** |

평가 10판 중 9판은 4스테이지(성역)의 전설까지 쓰러뜨리고 포털로 클리어했고, 1판은 3스테이지에서 죽었습니다(356,287점).
학습 중 한 판은 3스테이지 보스를 잡은 뒤 최종 대군 속에서 오래 버티며 11,016,780점을 냈습니다. 피해량 점수에는 상한이 없어서 생긴 이상치이고, 이 관찰이 "마지막 스테이지에서 포털 옆에서 버티다 들어가기" 전략으로 이어졌습니다.

학습된 경향(`npm run report`):
- 보스 호출 시각: 1스테이지 약 374초, 2스테이지 약 325초, 3스테이지 약 372초
- 마지막 보스 뒤 포털 옆에서 약 234초 더 버티고, 체력 47% 아래면 들어감
- 축복은 피해 > 공격속도 > 최대 체력 > 재생 순으로 선호
- 3등급 제단은 레벨 20 이후, 2등급은 레벨 10 이후에 시도

## 사용법

Node 18+와 Playwright(Chromium)가 필요합니다.

```bash
npm install            # playwright
npx playwright install chromium   # 처음 한 번 (이미 있으면 생략)

# 학습: 세대 수, 세대당 비교 쌍 수, 동시에 돌릴 브라우저 탭 수
npm run train -- --generations 20 --pairs 2 --workers 2

# 학습된 정책으로 플레이 (고속, 결과만 출력)
npm run play -- --runs 3

# 화면을 보면서 실제 속도로 플레이
npm run watch

# 학습 진행 상황 요약 (세대별 점수, 클리어율, 핵심 파라미터, 선호 선택지)
npm run report
```

학습은 언제든 Ctrl+C로 멈췄다가 같은 명령으로 이어서 할 수 있습니다(세대마다 `policy/policy.json`에 저장).
`runs/`에는 매 판의 상세 기록이 쌓입니다(git에는 올리지 않음).

옵션: `--species 4`(시작 포켓몬: 1 이상해씨, 4 파이리, 7 꼬부기), `--biome forest`, `--tier 0`(난이도).

기본 실행은 렌더링을 끈 고속 시뮬레이션입니다. 게임 로직은 1/60초 단위로 똑같이 진행되고 화면만 그리지 않습니다.
